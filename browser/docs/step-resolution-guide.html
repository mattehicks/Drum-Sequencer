Bars, beats, slots, and step resolution

D20 Synth Workbench — sequencer structure reference

Two independent axes

Structure — how many cells exist

Beats / measure (the global stepper, 2–12) times Slots per beat (per-row, 1–8, set either by typing into the row's own field or via the floating Beat N box's −/+ buttons). Changing either of these adds or removes actual step cells from the grid.

Timing — how fast the existing cells play

Step resolution — 1/8, 1/16, or 1/32 (seq.stepDivision) — multiplies seconds-per-step. It changes nothing about how many cells are on screen; it only changes how much real time passes between one cell and the next.

These two axes are orthogonal by design. Raising the step resolution does not add cells, and adding cells does not change how fast each one plays.

Worked example

  • Beats/measure = 4, Slots per beat = 4 → 16 cells total (the default grid).
  • Same 16 cells at Step = 1/16 (default): each cell is a sixteenth note, 4 cells per quarter-note beat, a 4/4 bar takes 4 beats to play through.
  • Same 16 cells at Step = 1/32: each cell now plays twice as fast, so the same 16-cell pattern finishes in half the time — same shape, compressed.
  • To get 32 distinct hittable cells in one bar (a true 32nd-note roll across the whole bar), you need Slots per beat = 8, not just a faster Step setting.

Why "16" and "8" don't type in

  • Beats / measure (callout 4) has no text box on this build — only the −/+ stepper buttons, capped 2–12. There is nothing to type a number into; clicking + repeatedly is currently the only way to raise it. This is almost certainly the "entering 16 does not work" report.
  • Slots per beat (callout 8) is a real number field and does accept typing, but its hard ceiling is 8 (SEQ_SLOTS_MIN=1, SEQ_SLOTS_MAX=8). Typing 16 gets silently clamped down to 8 on blur, with no visible message — which looks identical to the field "not working."
  • 8 slots/beat already matches the finest available step resolution (1/32 = eight 32nd-notes per quarter-note beat), so 8 is the correct current ceiling for this feature set, not a bug. The silent clamp with no feedback is worth fixing, and Beats / measure could get a typed-entry option the same way.

Toolbar and row controls

Numbers match the callouts in the screenshot above.

1

Tempo slider

Sets BPM. Pure timing, no effect on cell count.

2

Tap Tempo

Sets the same BPM by tapping in rhythm instead of dragging.

3

Step (resolution): 1/8, 1/16, 1/32

seq.stepDivision. How much real time one existing cell represents. Playback-speed multiplier only.

4

Beats / measure (global, 2–12)

How many beat-groups the shared bar has. Stepper only, no text box.

5

Zoom

Visual cell size on screen only, no effect on timing or count.

6

LINK / OWN (per row)

LINK follows the shared Beats/measure grid above. OWN gives the row its own independent measure, plus a LOOP/SYNC choice for how it relates to the shared bar.

7

Row volume (orange number)

This row's volume within the pattern (0–100), separate from the instrument's own Level.

8

Slots per beat (green number, per row)

rowSetUniformSlotsPerBeat(). Real text box, min 1, max 8.

9

One beat's worth of cells

The visible gap between groups of cells marks a beat boundary. Total visible cells for a row = beats (global, or the row's own if OWN) × slots per beat for that row.

10

Beat N floating box (per beat-group)

−/+ steps that one beat-group's own slot count (still capped 1–8, stepper only). C/P copy and paste one beat's pattern onto another.

Quick glossary

  • Bar / measure — the repeating structural unit, made of beats.
  • Beat — one pulse of the bar's beats/measure count.
  • Slot / step / cell — one hittable box in the grid; slots-per-beat sets how many exist inside each beat.
  • Step resolution — the note value one existing cell represents in real time (1/8, 1/16, 1/32); playback speed, not cell count.
